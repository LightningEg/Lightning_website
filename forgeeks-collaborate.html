01 / flow

Your first contribution.

A task is a GitHub issue. A branch is your separate workspace. A pull request asks us to review and add your changes to the official version.

01

Pick a task

Choose an unassigned good first issue. It says what's wrong, what finished looks like and which file to open.

02

Comment /take

A bot assigns it to you at once. One task at a time; /drop gives it back, and 14 quiet days free it for someone else.

03

Change it in a Codespace

Open a Codespace and press Create. The demo household opens in a preview tab. Edit, commit, then Sync; say yes when GitHub offers to make your fork.

04

Open a pull request

Press Compare & pull request, write Closes #37 with your issue's number and how you checked it. Tests run, we review and merge, and the issue closes.

// Codespaces are free within GitHub's monthly allowance; stop yours when you finish · your first pull request runs its tests once the owner approves · ask on the issue if you're stuck · the full guide

02 / who

Who can do what.

The owner controls merging and authorizes AI sessions to work through the existing owner account. Contributors keep their own accounts and work from forks.

peoplehow they work

  • [owner]

    OwnerControls repository settings and merging. May authorize AI sessions to review and merge through the connected owner account.

  • [team]

    Returning contributorsUse your own account, fork and branch. Coordinate on the GitHub issue before starting another task.

  • [open]

    New contributorsPick a known issue and send a pull request from your fork. You do not need the owner’s account or repository write access.

ai teammatesclaude, codex, luna

  • [write]

    Owner-authorized accessUse the existing connected owner account. Work on a branch and open a pull request. Contributors never receive owner credentials.

  • [merge]

    May merge, under rulesReview the latest changes, wait for passing checks and resolve discussions before merging authorized work. No separate AI account is required.

  • [never]

    NeverPush directly to main, skip checks, share owner credentials, or publish a release without authorization.

03 / gates

What a change must pass.

The owner and authorized AI sessions follow these checks before merging. Merging code does not authorize signing or publishing a release.

on every pull requestbefore merging

  • [pr]

    Pull request onlyNobody pushes to main. No force-push, no deletion, linear history.

  • [ci]

    Three green checkstests, dependency-review and analyze (CodeQL), up to date with main.

  • [owner]

    Maintainer reviewReview the actual changes and test results. AIs working through the owner account follow the owner’s authorization.

  • [fresh]

    Review the latest versionNew changes need another look. GitHub cannot record the owner account approving its own pull request.

  • [talk]

    Conversations resolvedAnswer questions and resolve review threads before merging.

sensitive changesneed owner authorization

  • [path]

    Workflows, rules and templatesChanges that run on machines need careful review and owner authorization.

  • [path]

    packaging/, android/, cloudflare/What ships to people’s devices.

  • [path]

    Scripts, and tests/conftest.pyCode that runs with a developer’s permissions.

  • [path]

    AGENTS.md, CLAUDE.md, LICENSE, SECURITY.mdThe rules and the legal text.

  • [path]

    v* release tagsOnly Admin creates them, and a release job waits for the owner’s click.

04 / rules

Ground rules.

Short, and the same for everyone.

01

Dummy data only

Never put real financial data, passwords, keys or screenshots of real money in a commit or issue. The demo household is fictional.

02

Security is private

A vulnerability goes to the private advisory form, never a public issue. Revoke a leaked secret first, then clean up.

03

Money lives in Python

Financial calculations stay in services, never templates or JavaScript. Say how a change can fail and show the test.

04

Brand and tests

Visible changes follow the guideline. Run the tests of what you changed; CI runs the full suite.

05 / ai

If you are an AI.

Claude, Codex and Luna cannot talk to each other, so the repo carries everything. Same pull request path, plus a hand-off.

01

Start from the repo

The repository is the only channel. Read NOW.md and the last 15 commits, then branch from a fresh main.

02

Claim long work

Work longer than one sitting goes in the Claimed table first, so two AIs never edit the same files.

03

Small finished steps

Test, commit and push each step. Findings become one file each in report/; fixing one deletes it.

04

Hand off

Changelog entry, update the files you touched, drop your claim, add next steps with a Read: line, then open the PR.
