Keep the existing proposal as its historical requirements source; its title does
not make every section current. Use explicit dated supersession and the operator
runbook for current operations. New work belongs in the shared app issue plan.
Move accepted product decisions or implemented contracts to their authoritative
reference instead of starting another proposal/status log.

Reports use reports/YYYY-MM-DD-subject/report.md with adjacent evidence/. Keep
raw submissions, private receipts, credentials and real financial data outside
public source. A report records a reviewed snapshot, not current deployment or
physical payment acceptance. Link shared references rather than copying them.
