01 / words

Six words, in plain English.

GitHub has its own vocabulary. You only need these six.

01

Issue

One task, written as a page. It says what is wrong, what finished looks like and which file to open.

02

Fork

Your own copy of Lightning on your own GitHub account. You can change it freely; the original stays untouched.

03

Codespace

A code editor that runs in your browser tab, with Lightning already installed. Nothing to set up on your computer.

04

Commit

Saving your change with a short note on what you did. Like a named save point you can come back to.

05

Pull request

A request that says: here is my change, please add it to Lightning. We read it, discuss it and, if it is good, merge it.

06

Merge

Your change joins the official version. The task closes itself and your name stays in the history.

02 / path

From a task to a merge.

Four steps. Each says what to click, what you should see and what to do if you don't.

1 · pick a task2 minutes

  • [open]

    Make a free GitHub accountAt github.com/signup. That is the only account you need.

  • [find]

    Open the list of good first issuesThese tasks are small, self-contained and nobody has them yet.

  • [read]

    Read the titleIt starts with a code like [3C]: milestone 3, item C of the plan. You don't need to understand the plan; the code only tells us where it belongs.

2 · take it10 seconds

  • [type]

    Comment /takeScroll to the comment box at the bottom of the issue, type /take, press Comment.

  • [bot]

    A bot assigns it to youYour name appears under Assignees within seconds. No one has to approve it.

  • [rule]

    One at a time/drop hands it back. If nothing happens for 14 days it is freed for someone else, unless your pull request is open.

3 · change ityour pace

  • [open]

    Open a CodespaceClick here and press Create codespace. Wait about a minute while it installs.

  • [see]

    The demo app opens in a preview tabMohab's household, with fictional data. It reloads when you save a file.

  • [edit]

    Edit the file the issue namesChange only what the issue asks for. Smaller changes are reviewed faster.

  • [test]

    Run its testIn the terminal at the bottom, for example python -m pytest tests/test_charts.py. You don't have to run everything: the pull request does that.

  • [save]

    Commit and syncOpen Source Control (left bar), write a short message, press Commit, then Sync or Publish Branch. When GitHub offers to create your fork, say yes.

4 · send it1 minute

  • [open]

    Press Compare & pull requestGitHub shows the button on the repository page right after you sync.

  • [write]

    Write two linesCloses #123 with your issue's number, and one line on how you checked it.

  • [wait]

    Your first test run waits for the ownerGitHub holds a newcomer's first run until the owner approves it. It is a one-click step on our side, not a problem with your change.

03 / after

What happens after you press send.

Nothing is lost and nothing is rushed. This is the order things go in.

01

Checks run

About five minutes. Three of them must pass: tests, dependency-review and analyze.

02

We review

We read the actual change. Questions come as comments on the pull request; answer them there.

03

We finish the paperwork

The changelog line, the docs and the brand-guideline details are ours to do. We push them to your branch, so don't worry about them.

04

Squash merge

Your commits join main as one tidy commit. The issue closes itself and we thank you on it.

04 / stuck

If something looks wrong.

The usual snags, and the way out of each.

common snagsand fixes

  • [bot]

    /take did nothingSomeone may already have it, or it has the taken label. Pick another; the list only shows unassigned ones.

  • [tab]

    The preview tab is blankGive the install another minute. Still blank: open the Ports tab and open port 8766.

  • [ci]

    A check turned redOpen Details next to it, read the last lines, fix the file, commit and sync again. The pull request updates itself.

  • [quiet]

    No answer for daysAIs don't watch GitHub on their own. Leave a comment on the pull request and the owner will ask for a review.

ask firstwhere to ask

  • [ask]

    Ask on the issueEvery question goes on the task, so the next person can read the answer too.

  • [private]

    Security problems stay privateFound a way to reach someone's data? Don't post it. Report it privately.

  • [chat]

    Prefer to chatDiscord is for quick questions. Anything about a task goes back on its issue.

05 / rules

Ground rules and the licence.

Short, and the same for everyone.

01

Fictional data only

Never put real financial data, passwords, keys or screenshots of real money in a commit or issue.

02

Nobody pushes to main

Every change, ours included, reaches main through a reviewed pull request.

03

Money lives in Python

Financial calculations stay in the Python services, never in templates or JavaScript.

04

You keep your copyright

Lightning is source-available under PolyForm Noncommercial 1.0.0. By sending a pull request you confirm the work is yours to give and let the owner use, change and relicense it, including commercially, as part of Lightning.

06 / product

What Lightning is.

A local-first money app for salaried people in Egypt. It runs on your own computer and phone; your data never has to leave them.

01

The loop

Record or import activity, sort out unclear names and categories, read the analysis, save towards goals.

02

Where vs what

Two questions stay apart: where value is held (CIB, the cash wallet, gold at home) and what is held (EGP, shares, fund units, gold grams, dollars).

03

Three layers

Ledger is real money. Plan is what-if and moves nothing. Report reads both and stores nothing. Every screen says which one a number comes from.

04

Where it ships

Mainly a Windows app with encrypted profiles, plus an Android phone app that hands the ledger to the PC over local Wi-Fi. Arabic (Egyptian) and English throughout.

what you can do todayfeature map

  • [ledger]

    Accounts and transactionsMoney in, out and between accounts; edit, void, restore, search; check an account against the bank.

  • [import]

    CSV and bank SMS importEvery row is reviewed before it posts; duplicates are flagged.

  • [plan]

    Budget and cash planningPlanned, spent and left; safe to spend; bills, loans, reserves and a three-month forecast.

  • [invest]

    Investments and goldTrades, positions, certificates, US stocks in USD, foreign cash, physical gold.

  • [egypt]

    Made for EgyptGam'eya savings circles, zakat estimate, EGX instruments, CIB and NBE SMS.

decisions that holdfor every change

  • [one]

    One name, one calculationEach figure has a single name and a single function. Screens never compute their own.

  • [local]

    Local firstProfile data and backups stay on your device, never in Git. Dummy data only while it is a beta.

  • [quiet]

    No silent resultsEvery action shows feedback. A wrong or silent result is worse than an extra click.

  • [brand]

    Strict brand guidelineCSS that differs from the guideline is wrong. Whole EGP on big figures, no coloured headers, no card in a card.

07 / built

How it is built.

A map before you open the code. Imports only point down, and a test fails the build if they don't.

the stackno frontend build

  • [py]

    Python 3.11+, FastAPIServer-rendered Jinja pages with plain JavaScript and CSS.

  • [db]

    One SQLite fileOrdered migrations and local backups; encrypted profiles with SQLCipher on the desktop.

  • [math]

    Money is never a floatDecimal in Python, scaled integers (_e6) in SQLite.

  • [net]

    Local onlyThe server listens on 127.0.0.1 and nothing else.

where things livetop depends on bottom

# imports only point down
ui/          routes, templates; no SQL, no maths
workflows/   use-cases across modules
planning/    bills, loans, forecast
services/    accounts, transactions, investments
reporting/   read-only queries
database/    SQLite, migrations, backups
core/        dates, money, posting rules
01

One writer

Only TransactionService writes postings. Everything else builds a validated posting and asks it.

02

Figures registry

lightning/core/figures.py names every figure, its layer and its function. Routes never compute them.

03

Try it

python -m lightning --demo opens Mohab's fictional household at http://127.0.0.1:8766, rebuilt on every start.

04

Mohab's year

tests/test_mohab_year.py lives a whole year through the screens. It is the acceptance test.

08 / terms

Lightning's own words.

One name and one meaning per term. If a name needs explaining, we rename it.

the basicsglossary

  • [ledger]

    AccountWhere value is held: CIB, the cash wallet, a brokerage.

  • [ledger]

    Financial assetWhat an account holds: EGP cash, a COMI share, a fund unit, a CD, a gram of gold.

  • [ledger]

    Holding / positionThe calculated quantity of one asset in one account on a date.

  • [ledger]

    BalanceAlways calculated from the ledger, never typed in.

  • [plan]

    PaydayThe day your salary usually arrives. The plan expects it then; nothing is recorded until the money lands.

made for egyptand gold

  • [ledger]

    Gam'eyaA rotating savings circle: one account per circle. Instalments and your payout are internal transfers, never income or spending.

  • [ledger]

    Physical itemA tangible asset such as a gold piece, tracked by weight, karat, cost and valuation.

  • [plan]

    Zakat dayThe date you pick once for counting zakat; the next is 354 days later. An estimate, never a ruling.

  • [plan]

    Instalment purchase (taqseet)A loan plan for an outstanding purchase. Creating it records no cash.

  • [report]

    Adjust balanceSet an account to a balance you know on a date; the difference is saved as one adjustment.

09 / team

How we work, and what is next.

The repository is the only channel, for people and AI teammates alike.

01

One file per fact

NOW.md is the hand-off, issues/ is the plan, CHANGELOG.md records every change, and the docs hold the rest.

02

Claim long work

Anything longer than one sitting goes in the Claimed table first, so two people never edit the same files.

03

Small finished steps

Test, commit and push each step. Each change gets a changelog line of three lines at most.

04

People first

An issue with an assignee belongs to that person. Nobody starts on it.
